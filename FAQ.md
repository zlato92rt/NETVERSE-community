# NETVERSE FAQ

NETVERSE is in active development. This FAQ covers the public project and community layer without exposing private production infrastructure.

## What is NETVERSE?

NETVERSE is being built as a network for shared compute resources, AI workloads and a creator and developer ecosystem.

## Is NETVERSE publicly launched?

No. NETVERSE is currently in active development and progressing toward public launch. Public materials describe the direction of the project and may change as development continues.

## Is the NETVERSE source code public?

The core production platform is private. This repository contains public-facing community materials, documentation, interface concepts and collaboration guidance.

## What can I do today?

You can follow the public roadmap, join GitHub Discussions and Discord, submit product feedback or feature ideas, improve public documentation, and report reproducible public-facing issues.

## Can I contribute compute resources today?

Public compute participation is not presented as production-ready yet. Before public launch, NETVERSE plans additional work around secure participation, workload isolation, reliability, observability, consent and production hardening.

## Are payments or rewards live?

Do not assume that public payment or reward functionality is production-ready. The public roadmap states that real payment and reward flows are enabled only after end-to-end verification.

## Is NETVERSE a cryptocurrency or investment?

NETVERSE is described here as a compute, AI and creator ecosystem. Community donations are voluntary contributions, not investments, and do not create ownership, profit rights, token rights or a promise of financial return.

## How do I report a bug or suggest a feature?

Use the repository issue templates. Please provide reproducible information for bugs and explain the problem or use case behind feature ideas.

## How do I report a security issue?

Do not publish vulnerabilities, exploit details, credentials or private keys in public issues or discussions. Follow [SECURITY.md](SECURITY.md) and use private security reporting when available.

## What information should never be posted publicly?

Do not submit secrets, private keys, seed phrases, access tokens, credentials, proprietary production code or sensitive infrastructure details.

## Where is NETVERSE heading next?

See the [Public Roadmap](ROADMAP.md). Current pre-launch priorities include security review, production hardening, reliable node connectivity, isolated compute execution, end-to-end payment verification, legal/support processes and public incident communication.
