# NETVERSE Platform Expansion Checklist

This checklist tracks public-distribution surfaces. Never store account passwords, recovery codes, API keys, private keys or social-media credentials in this repository.

## Tier 1 — must exist before public launch

### GitHub
Status: active.
Purpose:
- public source of truth;
- roadmap and verified status;
- waitlists;
- technical discussion;
- ambassador and builder recruitment.

### X
Status: active public handle in README.
Purpose:
- daily build-in-public updates;
- milestone threads;
- community replies;
- technical discussions.

### Discord
Status: active invite in README.
Purpose:
- early community;
- beta coordination;
- Q&A;
- ambassador coordination.

### LinkedIn
Owner action required if the official company page is not yet created or connected.
Purpose:
- founder/company credibility;
- investor/operator reach;
- hiring/partner visibility;
- milestone posts.

Recommended cadence: 3–5 useful posts per week.

### YouTube
Owner action required for channel setup/access.
Purpose:
- product demos;
- technical explainers;
- launch videos;
- long-form founder updates.

### Product Hunt
Owner action required for maker account and final launch scheduling.
Purpose:
- launch-day discovery;
- early adopter acquisition;
- maker/community feedback.

## Tier 2 — strong growth channels

### Reddit
Create an official identity only where useful.
Do not cross-post identical promotions.
Use community-specific technical discussions and feedback requests.

### Hacker News
Use for substantial technical milestones, Show HN and engineering write-ups.
Avoid routine promotional posts.

### Indie Hackers
Use for founder/build logs, experiments, metrics and market learning.

### DEV Community
Use for technical articles and architecture explanations.

### Hashnode
Use for engineering write-ups and build-in-public technical content.

### Medium
Use for polished product/thesis articles and press-friendly explainers.

### Bluesky
Use short-form milestone and founder updates.

### Threads
Use short product/community updates adapted from X content.

### Instagram
Use screenshots, short product stories, community visuals and Reels.

### TikTok
Use short explainers, demo clips and founder/build narratives.

### Facebook
Use official page plus relevant founder/startup/technology communities without spam.

### Telegram
Use announcement/community channel only if there is enough moderation capacity.

## Tier 3 — ecosystem and credibility surfaces

### Crunchbase
Owner action required for company/profile verification.
Purpose: company discovery and investor research.

### Wellfound
Owner action required.
Purpose: startup/company presence, future hiring and investor ecosystem visibility.

### Peerlist
Purpose: developer/founder presence and product discovery.

### BetaList and other beta directories
Use only when a real waitlist/beta path is ready.
Do not claim public availability if access is still gated.

### Startup directories / launch communities
Evaluate individually for quality and current activity before submission.

## Content reuse rule

One verified engineering milestone can be adapted into:
- X thread;
- LinkedIn post;
- Discord update;
- short video;
- technical article;
- GitHub status update.

Do not copy-paste the same text everywhere. Adapt format and context.

## Account-access boundary

ChatGPT can prepare copy, campaign structure, public GitHub materials and connected-tool workflows.

The project owner must help when a platform requires:
- creating an official account;
- accepting terms;
- solving CAPTCHA;
- email/SMS/2FA verification;
- granting social publishing permissions;
- linking payment/advertising accounts;
- confirming legal/company identity.

No credential should ever be pasted into a public issue or committed to GitHub.

## First expansion sequence

1. Ensure official LinkedIn company presence.
2. Ensure YouTube channel.
3. Prepare Product Hunt maker profile and teaser.
4. Open Instagram + Threads if brand handles are available.
5. Open Bluesky.
6. Establish Reddit/Hacker News founder identities through genuine participation.
7. Publish DEV/Hashnode/Medium technical articles.
8. Add startup/company directory profiles where relevant.
9. Localize top public materials through ambassador program.
10. Track acquisition source so growth decisions use real data.
